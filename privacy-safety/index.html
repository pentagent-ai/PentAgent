Privacy & safety

What stays on your computer, what leaves it, and the controls around live requests. This page describes pilot build 0.1.0-trial10.7. The full details are in the Privacy Policy.

What stays on your computer

Captured traffic, projects, findings, chats and your AI settings are stored in the PentAgent data folder on your computer. The backup PentAgent makes before updating your data stays in that folder too. PentAgent doesn’t run a server that receives your traffic or projects.

What leaves your computer

  • To the AI provider you choose: the requests, responses and notes you send to it in Ask, Plan or Agent, plus your API key for that provider.
  • To our sign-in service: your GitHub sign-in, your Terms and Privacy acceptance, and checks for app updates and pilot settings. There is no approval step: any GitHub account can sign in. It records your GitHub username, email and the times of your first and latest sign-in, so we can count users and block accounts that misuse PentAgent. The app also shows your GitHub name and profile picture. It never receives captured traffic, projects or API keys.
  • Anonymous usage analytics (PostHog, EU): these start only after you accept the welcome screen. They include a random install ID, the app version, your operating system and which features you use, such as opening a tab or running the Fuzzer. They never include your name, GitHub account, URLs, traffic or keys. Error reports are scrubbed before sending.
  • First-launch setup: PentAgent downloads its Python packages and the isolated lab browser.
  • Your tests: requests you send go to the app you’re testing.

Where your API key lives

Your AI provider key is saved in a settings file in the PentAgent data folder on your computer. It’s stored as plain text, not in the system keychain, and on macOS and Linux only your user account can read the file. PentAgent sends the key only to the provider address you set up.

The honest limit

Your AI provider sees everything you send it, including tokens, cookies or personal data inside captured traffic. PentAgent doesn’t mask them. For sensitive or client work, use a local or self-hosted model. PentAgent supports llama.cpp and LM Studio, Ollama-compatible servers and any OpenAI-compatible endpoint, alongside Groq, Google Gemini and OpenRouter.

Safe by design

  • Agent asks first. Each live request the agent wants to send shows Allow this request? with Deny, Stop and Allow. Ask and Plan can’t send live requests, and the agent only sends to hosts in your project’s scope.
  • Batch approval is your choice. In AI settings you can let one Allow cover the rest of a run. It’s off by default, and payloads that could destroy data still ask every time.
  • Stop. Stop attack ends the agent’s run and disarms it, so it can’t send again until you start a new attack. A Fuzzer or Sequencer job the agent already started keeps going until you stop it in its own tab or on the Dashboard.
  • Spend cap. Off by default. Turn it on to set a per-session or daily limit in money or tokens. When a limit is reached, the assistant stops before its next model call. Money limits need a provider that reports cost.
  • Your own tools. Repeater and Fuzzer send when you click Send or Start attack.

Start in a practice lab

Try PentAgent on a deliberately vulnerable app running on your own computer, such as OWASP Juice Shop or bWAPP. Only test apps you own or have permission to test.
